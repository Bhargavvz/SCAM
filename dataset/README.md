# Inventory & Supply Chain Dataset - Memory & Decision Agent extension (v1.1.0-ext)

Synthetic, fictional extension of **Analytics Engineering, "Inventory & Supply Chain Dataset v1.0.0"**
(https://www.analyticsengineering.com/datasets/inventory-supply-chain), licensed **CC BY 4.0**
(https://creativecommons.org/licenses/by/4.0/). The original seven tables are included **unchanged**; everything
else was generated by the code in this folder (seed 20250905, scale `default`).
All suppliers, plants, brands, materials, people and events are fictional. No PII. This extension is also released under CC BY 4.0.

## How it was built (and the rules it keeps)

1. **Profile first** (`profile.py`) - every scale / rate / category parameter comes from the source (see `calibration.json`).
2. **Additive only** - source rows are never modified; `validate.py` checks row counts + content hashes of the inputs and of the SQLite copy.
3. **Causality** - RM deliveries follow supplier reliability, quoted lead time, country / season shocks and planted patterns;
   RM stock is simulated by a time-phased MRP. Existing FG lateness is uniform in v1.0.0 (not related to reliability), so FG-side
   events are *mined* clusters (binomial tests) and the RM side is built to explain existing late / short FG receipts.
4. **Cascade back-fill** - for ~12% of eligible late/short make-product FG lines: RM PO slip (rm_po_revisions) -> RM stock below safety ->
   run blocked at its planned start (`production_runs.delay_reason_code = rm_shortage`) -> the existing FG receipt is late. Every chain is
   re-checked against the full stock trajectory (strict date order, run could not have started earlier, no negative stock).
5. **Outcomes are computed, not sampled** - decision costs / stockout days, commitment statuses and scorecards come from the trajectories
   (`consequences.py` holds the deterministic cost model shared with the holdout simulator).
6. **Identities** - RM: opening + cumulative movements = weekly on-hand; consumption = produced_qty x qty_per_unit x (1 + scrap_pct/100);
   demand: fulfilled_units = -SUM(existing sale quantity_change) per product / warehouse / week.

## Key modelling notes

- Make products (`products_ext.sourcing_mode = make`) are produced at `plant_id`; their existing FG PO is read as the replenishment order from
  the plant, and the PO's supplier as the tolling partner operating the line.
- `product_demand_weekly` is sparse (weeks with demand or a non-zero forecast) because source sales are intermittent
  (1.16% of product-warehouse-weeks have sales).
- `unfulfilled_units > 0` only where existing stock hit <= 0 or a logged event explains it (customer allocation during a supply cascade,
  DC disruption, demand spike).
- `decisions.outcome_attribution` (extension column): as_expected | context_shift (worked before, failed under different conditions) |
  bad_luck (best ex-ante, failed through an outside event) | decision_quality.
- Extra key columns not in the brief: `rm_supplier_catalog.catalog_id`, `rm_po_revisions.revision_id`, `rm_purchase_orders.order_type`,
  `commitments.evidence_ids`, corpus field `supersedes`.

## Memory corpus (`memory_corpus.jsonl`)

Fields: doc_id, timestamp (ISO-8601, business hours), context, content, doc_type, entity_ids, source_record_ids, split (memory | holdout),
is_noise, supersedes. Docs are rendered from structured facts by a seeded template grammar (>=15 variants per doc type) and form stories of
3+ docs written days/weeks apart by different roles. ~27% are low-signal noise; >=10% update or supersede an earlier doc. Docs dated from
2025-10-01 are `split=holdout` and must not be ingested. Optional `--llm-narratives` rewrites docs through a cached,
resumable, provider-agnostic LLM interface with a fact-lock check (`llm_narratives.py`).

```

python run_all.py --input <folder|zip|sqlite of v1.0.0> --output out --seed 20250905 --scale default   # ~5-10 min
python run_all.py --input ... --output out_small --scale small                                          # dev corpus (~300 docs)
python validate.py --input ... --output out                                                              # fail-loud checks
python hindsight_loader.py --corpus out/memory_corpus.jsonl --bank supply-chain-memory --dry-run
```
